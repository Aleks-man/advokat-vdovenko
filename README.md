# Константин Вдовенко — сайт адвоката

Сайт-визитка Константина Вдовенко, адвоката по уголовным делам. Четыре страницы: главная, уголовная защита, обо мне и контакты.

Интерфейс — React и TypeScript, разработка и сборка — Vite. Маршруты — React Router, иконки — Lucide. Крупные заголовки и имя набраны Georgia, подзаголовки, основной текст и элементы интерфейса — Onest. Onest загружается локально; Georgia — системный шрифт. Размеры, насыщенность и цвета текста заданы общими переменными в tokens.css. Вёрстка адаптирована для компьютеров, планшетов и телефонов.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm ci
npm run dev
```

Сайт открывается на http://127.0.0.1:5173, API — на http://127.0.0.1:3001/api/health. Оба приложения запускаются из корня через npm workspaces.

## Структура

```text
front/src/
  app/          — маршрутизация
  components/   — общие блоки и их стили
  pages/        — страницы
  data/         — контакты, навигация, направления работы
  styles/       — шрифты, общие стили и переменные

back/src/
  config/       — переменные окружения
  db/           — подключение PostgreSQL
  routes/       — маршруты API

tests/browser/  — браузерные проверки
```

Контакты и навигация — в `front/src/data/site.ts`, порядок работы — в `front/src/data/workSteps.ts`, направления защиты — в `front/src/data/practice.ts`, вопросы и ответы — в `front/src/data/faq.ts`, полезные заметки — в `front/src/data/usefulMaterials.ts`. Цвета и размеры — в `front/src/styles/tokens.css`, подключение шрифтов — в `front/src/styles/fonts.css`.

Общий логотип с именем — `front/src/components/Brand/`. Контактные ссылки формируются в `front/src/data/contacts.ts` из данных `site.ts`. Стили общих блоков лежат рядом с компонентами; глобальные правила — в `styles/`. Блоки, которые используются только на одной странице, находятся в `pages/<Page>/components/<Block>/`: разметка и CSS лежат рядом. Файл страницы задаёт порядок блоков, её CSS отвечает только за общую раскладку. Если собственных стилей у страницы нет, отдельный CSS-файл не создаётся.

## Проверки

```sh
npm run typecheck
npm test
npm run test:browser
npm run build
npm run format:check
```

Для форматирования — `npm run format`. Браузерные тесты используют Google Chrome; настройки находятся в `playwright.config.ts`. Скриншоты сохраняются в `artifacts/`, каталог исключён из Git.

## API и база данных

Сервер работает на Express и TypeScript. Сейчас доступен health endpoint; для запуска PostgreSQL не требуется. Настройки подключения к базе — в `back/.env`, образец — `back/.env.example`. Подключение использует `DATABASE_URL`.

## Публикация на Vercel

Сейчас публикуется только фронтенд. Бэкенд остаётся заготовкой: сервер Express и PostgreSQL для сайта не нужны. Конфигурация находится в корневом `vercel.json`.

При первом подключении:

1. Импортировать Git-репозиторий в Vercel.
2. Оставить Root Directory в корне репозитория (`./`), а не `front`.
3. Выбрать Framework Preset — Vite. Установка, сборка и выходной каталог заданы в `vercel.json`: `npm ci`, `npm run build -w front`, `front/dist`.
4. Выбрать Production Branch в настройках Git проекта и запустить Deploy.

При подключённой Git-интеграции пуш в production-ветку автоматически запускает публикацию новой версии. Для остальных веток и pull request Vercel создаёт preview-развёртывания согласно настройкам проекта.

Правило `rewrites` передаёт маршруты React Router в `index.html`. Благодаря этому `/practice`, `/about`, `/contacts` и старый адрес `/approach` работают при прямом открытии и обновлении страницы. Неизвестные адреса показывают страницу NotFound внутри приложения; HTTP-статус при таком SPA fallback — 200.

Проверка сборки перед публикацией:

```sh
npm run build -w front
```

После деплоя проверить прямое открытие и обновление каждой страницы, переход `/approach` на `/about`, ссылки на этапы `/practice#stage-01`, фотографии, шрифты и мобильное меню. Перед запуском для клиентов заменить тестовые контакты в `front/src/data/site.ts`.

Переменные окружения для текущего фронтенда не требуются. Прокси `/api` в `front/vite.config.ts` работает только при локальной разработке; при подключении бэкенда его production-адрес и маршруты нужно настроить отдельно.

Документация: [Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite), [деплой из Git](https://vercel.com/docs/git).
